# Comment API

Covers what's implemented so far: creating a comment and listing comments for a post.

## Create a comment

**Where each field comes from — this is the important part**

The request body must NOT include `post_id` or `user_id`. Only `text` and (optionally) `parent_comment_id` come from the client:

```json
{
  "text": "Great point!",
  "parent_comment_id": null
}
```

- `post_id` is taken from the URL path (e.g. `/posts/{id}/comments`), not from the body. This avoids a mismatch between the URL and a value the client could send in the body.
- `user_id` (the author) is taken from the authenticated user's context (set by the auth middleware after validating the JWT), never from the body. If it came from the body, anyone could post a comment "as" another user.
- `parent_comment_id` is optional. Omit it (or send `null`) for a top-level comment. A comment cannot be its own parent (enforced by a `CHECK` constraint in the schema).

**Response**

Returns the full created comment, including `id`, `created_at`, and `updated_at` — these are generated by the database (via `DEFAULT CURRENT_TIMESTAMP` and the auto-incremented `id`), not set by the client, so the response is the only way to know them right after creation.

`user_id` and `parent_comment_id` can be `null` in the response — a comment's author can become `null` if the user account is later deleted, and `parent_comment_id` is `null` for top-level comments.

## Get all comments for a post

**Pagination**

The endpoint always paginates — there's no "give me everything" mode. Query parameters:

- `page` — defaults to `1` if not provided. Must be `>= 1`.
- `size` — defaults to `20` if not provided. Must be `> 0`.

Example: `GET /posts/5/comments?page=2&size=10`

**Response shape**

```json
{
  "comments": [...],
  "page": 2,
  "size": 10,
  "total": 47
}
```

`total` is the total number of comments for that post (not the whole forum) — it's what the frontend needs to render page controls.

**Post scoping**

`post_id` comes from the URL (same as in Create), and every query — both fetching the page of comments and counting the total — filters `WHERE post_id = ?`. This is also why the `idx_comment_post_id` index exists: it makes this filter fast even as the number of comments grows, instead of scanning the whole `comment` table on every request.
