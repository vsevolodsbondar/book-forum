# Comment API

Covers the Comment endpoints: create, list (by post), update, delete — and the shared error response format.


## Errors

Every error response uses the same JSON envelope, produced by a shared `GlobalErrorHandler`:

```json
{
  "status": 404,
  "message": "The comment with this id doesn't exist"
}
```

The HTTP status code matches `status` in the body. Sentinel errors map to status codes like this:

| Sentinel error | HTTP status | Meaning |
|---|---|---|
| `ErrPostNotFound`, `ErrCommentNotFound`, `ErrCategoryNotFound`, `ErrUserNotFound` | 404 | The referenced resource doesn't exist |
| `ErrForbidden` | 403 | Authenticated, but not allowed to do this (not the author, or the comment is protected) |
| `ErrInvalidInput`, `ErrNoChange`, `ErrBadRequest`, `ErrUserRegisterError` | 400 | Malformed or pointless request |
| `ErrWrongCredentials` | 401 | Login failed |
| `ErrExpiredSession` | 401 | Session token missing/invalid/expired |
| anything else | 500 | Unexpected internal failure; logged server-side, message not leaked to the client |

## Create a comment

`POST /posts/{id}/comments`

**Where each field comes from**

The request body must NOT include `post_id` or `user_id`. Only `text` and (optionally) `parent_comment_id` come from the client:

```json
{
  "text": "Great point!",
  "parent_comment_id": null
}
```

- `post_id` is taken from the URL path, not the body — avoids a mismatch between the URL and a value the client could send in the body.
- `user_id` (the author) comes from the authenticated session, never from the body — otherwise anyone could post a comment "as" another user.
- `parent_comment_id` is optional. Omit it (or send `null`) for a top-level comment. A comment cannot be its own parent (enforced by a `CHECK` constraint in the schema).

**Behavior**

- Rejects with `ErrPostNotFound` (404) if `post_id` doesn't refer to an existing post.

**Response**

Returns the full created comment, including `id`, `created_at`, and `updated_at` — generated by the database, not the client.

`user_id` and `parent_comment_id` can be `null` in the response — `user_id` becomes `null` if the author's account is later deleted, and `parent_comment_id` is `null` for top-level comments.

## Get all comments for a post

`GET /posts/{id}/comments`

**Pagination**

The endpoint always paginates — there's no "give me everything" mode. Query parameters:

- `page` — defaults to `1` if not provided. Must be `>= 1`.
- `size` — defaults to `20` if not provided. Must be `> 0`.

Example: `GET /posts/5/comments?page=2&size=10`

**Behavior**

- Rejects with `ErrPostNotFound` (404) if `post_id` doesn't refer to an existing post.
- `post_id` scopes every query (the comment page, the total count, and the post's own title/category) — this is also why the `idx_comment_post_id` index exists, so the filter stays fast as comments grow.

**Response shape**

```json
{
  "title": "Best sci-fi of the 90s",
  "category": "Sci-Fi",
  "page": 2,
  "size": 10,
  "total": 47,
  "comments": [
    {
      "id": 12,
      "text": "Completely agree",
      "post_id": 5,
      "user_id": 3,
      "parent_comment_id": null,
      "updated_at": "2026-09-17T10:02:00Z",
      "likes": 4,
      "dislikes": 0,
      "is_liked": true,
      "is_disliked": false,
      "user_for_comment": {
        "username": "Alice",
        "image": ""
      }
    }
  ]
}
```

`title`/`category` describe the post itself (one value for the whole page, not per comment) — `category` comes back empty if the post has no category.

Per comment:
- `likes`/`dislikes` are counts across all users for that comment.
- `is_liked`/`is_disliked` reflect only the *current* caller's own reaction. For an anonymous visitor these are always `false`.
- `user_for_comment.username` is `"Deleted user"` and `image` is `""` if the comment's author account has been deleted — the comment itself is never removed just because its author is.

## Update a comment

`PATCH /comments/{id}`

Unlike Create and GetAllByPostID, the comment's own id comes from the URL here, not a `post_id` — a comment has its own identity, so a point operation on one specific comment addresses it directly.

**Request body**

```json
{
  "text": "Updated text"
}
```

Only `text` can be changed. `post_id`, `user_id`, and `parent_comment_id` are not editable through this endpoint.

**Behavior**

- Rejects with `ErrCommentNotFound` (404) if the comment doesn't exist.
- Rejects with `ErrForbidden` (403) if the caller isn't the comment's author (including when the author has since been deleted — nobody can edit an authorless comment).
- Empty/blank text is rejected (`ErrInvalidInput`, 400) before touching the database.
- Rejects with `ErrNoChange` (400) if the new text is identical to the current text.
- `updated_at` is set to the current time (UTC) by the server; the client never sends it.

**Response**

Returns the updated comment (`id`, `text`, `updated_at`).

## Delete a comment

`DELETE /comments/{id}`

**Behavior is not a plain delete — two special cases:**

- **A post's initial comment (`post.init_comment_id`) cannot be deleted directly** (`ErrForbidden`, 403). Since a post's "body" is really its first comment, deleting it would leave the post without content — delete the post instead.
- **A comment that other comments reply to** (has a `parent_comment_id` pointing to it) is not physically deleted. Instead, its `text` is replaced with a placeholder ("Deleted message") and `user_id` is set to `null` — it stays in place so replies remain valid, but shows as removed.
- **A comment with no replies that isn't a post's initial comment** is deleted normally. Its own likes are removed automatically via `ON DELETE CASCADE`.

**Behavior**

- Rejects with `ErrCommentNotFound` (404) if the comment doesn't exist.
- Rejects with `ErrForbidden` (403) if the caller isn't the comment's author (checked before either the delete or the reset happens, so this applies to both cases above).

Returns `204 No Content` on success.
